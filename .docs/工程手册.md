# 工程手册 · 数字营销平台

本文记录**本仓库**怎么开起来、怎么部署、以及从原型模板拷贝后要注意什么。细节对照表见 [项目对照表.md](./项目对照表.md)。

---

## 1. 仓库长什么样

```
digital-marketing/            ← Cursor 打开的仓库根
├── web/                     ← 【唯一】前端工程（Umi Max / Ant Design Pro）
├── .docs/                   ← 本手册（启动前 / 换机必读）
├── .github/workflows/       ← GitHub Pages 自动部署（工作目录 = web/）
├── README.md                ← 入口指路到本目录
├── .gitignore               ← 只允许提交 web / .docs / .github 等
├── 文档/                    ← 本地需求/调研/打标分析（不进 Git、不部署）
└── （其它本地文件夹）        ← 一律当本地资料，不进 Git
```

| 路径 | 是否 Git | 是否部署 |
|------|----------|----------|
| `web/` | ✅ | ✅（构建产物） |
| `.docs/` | ✅ | ❌（给人 / AI 读） |
| `.github/` | ✅ | ❌（CI 自己用） |
| `文档/`、分析代码、`小程序代码` 等 | ❌ | ❌ |

## 2. 本项目从哪来（模板拷贝注意）

- 源自母版：`D:\dev\projects\antd-prototype-starter`（Ant Design Pro v6 simple）。  
- **不要在母版上直接改客户业务**；每个客户 = 独立文件夹 = 独立 GitHub 仓库。  
- 拷贝后应：**删掉拷贝来的 `.git` → `git init`**，再按对照表改英文仓库名 / `PUBLIC_PATH`。完整步骤见 [原型指南.md](./原型指南.md)。  
- **本仓库已演进为「根目录 + `web/` 工程」**：安装、脚本、源码都以 `web/` 为根；CI 的 `working-directory` 也是 `web`。新建模板若仍是「工程在仓库根」，对齐时务必改 CI 与文档，勿混用两套路径。

### 拷贝时绝对不要做的事

1. **不要拷贝 `node_modules`**  
   - 依赖由 `pnpm install` 根据 lockfile **安装/链接**而来，不是工程源码。  
   - Windows + 中文路径下整目录复制极易失败（超长路径、EPERM、半残目录），还浪费时间。  
   - 正确做法：只带源码与 `pnpm-lock.yaml`，到目标机 `cd web` 后重新 `pnpm install`。

2. **不要拷贝 `dist`、`.umi*`、`.turbo` 等构建缓存**  
   - 本地开发 / CI 都会重新生成。

3. **不要把多个客户的业务塞进同一个仓库**  
   - Demo 链接、`PUBLIC_PATH`、仓库名会互相踩。

4. **不要用中文当 GitHub 仓库名 / `PUBLIC_PATH`**  
   - 本地文件夹用英文（本仓库：`digital-marketing`）；远程仓库名 / `PUBLIC_PATH` 以对照表为准，不要用中文。

## 3. 环境与依赖（安装）

| 项 | 要求 |
|----|------|
| Node.js | 22+（与 CI 一致） |
| 包管理器 | pnpm 9 |
| 推荐 store | `D:\dev\pnpm-store`（本机已约定时可跳过） |

```powershell
# 可选：统一 pnpm store，避免每个盘各拷一份包
pnpm config set store-dir D:\dev\pnpm-store

cd D:\dev\projects\digital-marketing\web
pnpm install
pnpm start
```

- 本地地址：http://localhost:8000  
- 演示账号：见 [项目对照表.md](./项目对照表.md) / `web/README.md`（常用 `admin` / `123456`）

### Windows + 中文路径常见坑

- 偶发 `ERR_PNPM_EPERM`（esbuild 等 rename 失败）：`web/.npmrc` 已设 `package-import-method=copy`（及必要时 `node-linker=hoisted`），**用安装，不要用拷贝别人的 node_modules 绕过**。  
- 典型表现：`reused` 很多、`added` 将近完成，最后卡在 `esbuild_tmp_*` → `esbuild` 的 rename。完整说明与单进程处理步骤见 [Windows-pnpm-esbuild-EPERM.md](./Windows-pnpm-esbuild-EPERM.md)。  
- 安装失败时：删掉 `web/node_modules`（或至少删掉出错的 `.pnpm\esbuild@…`）后重跑 `pnpm install`（仍不要从别处复制）。  
- 仓库根**没有** `package.json`；**必须**进入 `web/` 再安装与启动。  
- **禁止并行开第二个** `pnpm install` 抢同一 `web/node_modules`。

## 4. 日常开发节奏

1. 在 `web/` 改代码与 Mock。  
2. `pnpm start`，浏览器自己验收（不要默认让 AI 开浏览器点菜单）。  
3. **未明确要求时：不 `git commit`、不 `git push`、不触发部署。**  
4. 只有你说「推到 GitHub / 部署一波 / 可以上线了」时，才提交并 `push main`。

国内 push GitHub 通常需要代理（常见端口 **7892**）。

## 5. 部署 GitHub Pages（步骤）

对照表：

| 项 | 值 |
|----|-----|
| 仓库 | `digital-marketing-platform-demo` |
| Demo | https://wu98455.github.io/digital-marketing-platform-demo/ |
| `PUBLIC_PATH` | `/digital-marketing-platform-demo/` |

### 5.1 流水线在做什么

推送 `main` 后，`.github/workflows/deploy-pages.yml`：

1. `working-directory: web`  
2. `pnpm install` → `max setup` → `pnpm run build:pages`  
3. 把 `web/dist` 发到 `gh-pages` 分支  

本地预构建（可选）：

```powershell
cd web
pnpm run build:pages
```

### 5.2 首次启用 Pages（若尚未配置）

1. 仓库 **Settings → Pages**  
2. **Deploy from a branch** → 选 **`gh-pages`** → **/ (root)**  
3. 等 1～2 分钟打开 Demo 链接验证登录

### 5.3 部署时注意

- 改 `PUBLIC_PATH` / 仓库名必须**对照表、CI、`web/package.json` 的 build:pages 一起改**，否则静态资源 404。  
- 不要把 `文档/`、分析用小程序代码推进仓库「顺便部署」——它们本就不在 Git 跟踪范围内。  
- Actions 失败时先看是否 lockfile 与 `web/package.json` 不一致、或 Node/pnpm 版本偏离手册。

## 6. 给 AI / 后人的执行摘要

1. 打开仓库根 → 先读 `.docs/README.md` 与对照表。  
2. 只在 `web/` 里 `pnpm install` / `pnpm start`。  
3. **禁止**复制 `node_modules`；依赖用 pnpm store 安装。  
4. 业务与路由在 `web/config`、`web/src`、`web/mock`。  
5. 部署仅在用户明确要求后 `push main`；代理按需开启。  
6. `文档/` 等本地资料可继续放磁盘，但不要 `git add`。
