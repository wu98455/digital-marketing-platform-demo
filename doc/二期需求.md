## 2. 二期明确要做的需求

### 2.1 经营分析深化

一期已有看板骨架。二期可增强：真实中台指标、自定义看板、登录默认页策略细化等。

原 §2.1 看板能力已在一期落地，本节仅保留深化项。

### 2.2 标签共享 / 审核 / 公共标签库

- 普通用户之间的标签共享、申请与审核
- 公共标签库、相似规则复用策略
- 跨人可见与防重复创建的完整规则

一期仅为：**本人私有 + 超管全量**，无共享。

### 2.3 全链路营销画布（复杂编排）

一期已具备最小旅程能力：

- 选人双来源（目标人群 / 人群标签）
- 触达方式三渠道（发短信 / 企微发消息 / 小程序发券）
- 等待 + 「是否购买」双出边分支（边标签：已购买 / 未购买）

二期继续：

- 多条件判断、多阶段编排、渠道响应、属性/订单查询全家桶等
- 更复杂的合并/拆分/排除与真实订单中台联动的分支判定

### 2.4 跨分中心数据打通

- 跨中心混筛、跨中心标签/人群互通
- 一期：下发中台必须带单据所选分中心；中心间数据隔离

### 2.5 常用 / 收藏在选标场景的全面铺开

一期已在：

- 人群标签列表三 Tab
- 目标人群新建 · 圈选条件 · 总标签库：**只看常用 / 只看个人收藏**（二选一勾选）

二期建议继续覆盖：

- 客户/店铺/商品/专题活动的打标弹层（`TagPickerModal`）
- 「常用」是否改为按真实选用次数/服务端统计（一期为 localStorage）

> 画布选人 · 人群标签侧已支持「只看常用 / 只看个人收藏」（二选一）。

### 2.6 活动与人群的协作共享

- 活动默认本人可见可编；是否允许同事只读/协作编辑
- 目标人群跨人复用策略

### 2.7 正式对接中台 / 生产能力

- OneID、预览 SQL、按分中心筛数：由演示 Mock 升级为真实中台接口
- 执行结果、触达明细与真实投放通道对齐

## 3. 不确定 / 待拍板需求（二期前需确认）

| 编号 | 议题 | 现状 / 一期处理 | 待确认点 |
|---|---|---|---|
| U1 | 经营分析是否作为登录默认首页 | 一期已默认 `/analytics` | 是否改回人群标签或可配置 |
| U2 | 「客户」与「人群标签」两套标签库是否长期并存 | 圈选五库标签页中两者均用 customer 库数据 | 是否合并为一个库，或客户库独立运营口径 |
| U3 | 目标人群圈选是否允许「仅维度、不选标签」 | 一期：**标签必选**，维度可选 | 业务是否要放开仅维度圈选 |
| U4 | 标签重名范围 | 一期：同库标签名全局不可重复 | 是否改为「同分类下不可重复」或允许超管强制同名 |
| U5 | 二次打标是否允许追加到已有标签 | 一期：只新建人群标签 | 是否增加「追加到已有标签」 |
| U6 | 执行结果入口是否同时保留在「营销活动」列表 | 一期：执行记录为主；活动列表仍可有执行结果 | 是否只保留执行记录一处，避免双路径 |
| U7 | 创建来源列（目标人群） | 一期已去掉（价值低） | 二期若有多入口（导入/API/标签生成）是否恢复 |
| U8 | 预览 SQL 是否展示真实 SQL 文本 | 一期为分中心 + 维度说明清单 | 专业用户是否需要可复制的 SQL |
| U9 | 角色权限树交互 | 一期：弹窗固定高度，展开树加长内容区内滚动 | 是否改为抽屉/分步向导 |
| U10 | 组织架构、菜单管理深度 | 有基础原型 | 是否纳入二期正式权限模型 |

## 4. 建议二期优先级（供排期）

| 优先级 | 主题 | 理由 |
|---|---|---|
| P0 | 经营分析页 | 业务强诉求；一期已设计未上菜单 |
| P0 | 中台正式对接（OneID / 筛数 / 触达） | 从演示到可试用 |
| P1 | 选标场景常用/收藏全覆盖 | 与一期列表能力一致，降选用成本 |
| P1 | 二次打标增强（可选追加已有标签） | 依赖 U5 拍板 |
| P2 | 标签共享与审核 | 组织协作刚需，规则重 |
| P2 | 画布能力回补 | 复杂度高，按场景增量 |
| P3 | 跨分中心打通 | 依赖数据与合规 |
